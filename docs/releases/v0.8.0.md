# Hecate v0.8.0

This release makes work policies enforceable across native Tasks and Hecate Chat,
and puts operator-reviewed executable identity ahead of External Agent execution.

## Highlights

- Standalone native Tasks can use Work policies to carry an Agent Preset, model routing, tool access, approval posture, and workspace/network restrictions into execution.
- Agent Preset and Hecate Chat approval policies now reach the native runtime without weakening stricter runtime, browser, or MCP restrictions.
- External Agents show the detected executable path, SHA-256 identity, approval status, and changes since approval in Connections.
- External Agent discovery is passive: opening Chats or Connections no longer launches diagnostic processes. Checks, authentication, and agent launches require approval of the current executable identity.
- Runtime and UI dependencies are refreshed, with OpenTelemetry export compatibility preserved.

## Security

- External Agent approval is bound to the runtime host, adapter, resolved executable, and measured file identity. Hecate rechecks identity before starting a process and refuses an unapproved or changed executable.
- Approval records which executable the operator accepted; it does not verify the publisher or establish that the program is malware-free. Launcher-only approval covers the launcher, not its interpreter or downstream programs. Install agents through trusted vendor channels.
- Preset-backed native work cannot use an approval policy to bypass disabled tools, read-only workspace restrictions, network restrictions, or mandatory browser/MCP policy.
- No credential rotation is required for this release.

## Breaking or risky changes

- After upgrading, open **Connections** and review and approve each External Agent executable before using it, including previously configured agents. Discovery alone does not run the executable. An agent update or identity change requires a fresh approval.
- Revoking executable approval blocks future launches; it does not terminate an already-running direct ACP peer. Stop active work separately when needed.
- New preset-backed native Tasks and Hecate Chat sessions freeze their approval posture. Editing a preset later does not rewrite existing work; legacy Task and Chat snapshots without an explicit approval posture retain their previous behavior.
- Persistent SQLite and Postgres stores create executable-trust storage automatically at startup; approval records require an explicit operator decision. Memory-backed approvals last only for the runtime process. Back up persistent data before upgrading; no manual migration command is required.

## Verification

- Release gate: `just verify`, including Go unit/race tests, vet, Docker smoke, UI unit/browser tests, documentation checks, and a production build.
- Release packaging validates native desktop bundles, unsigned iOS Simulator and Android debug compilation, and signed desktop updater payloads.

## Known limitations

- Hecate remains pre-1.0. Review the tracked [known limitations](https://github.com/hecatehq/hecate/blob/master/docs/operator/known-limitations.md) before upgrading.
- External Agents remain trusted local programs with their own accounts, billing, and runtime loops; Hecate supervises but does not sandbox them. Path-based process execution retains a narrow same-user replacement window after the final identity check.
- Native Work policies do not impose Hecate's tool or approval policy on External Agent runtime loops. Hecate Chat does not acquire browser-interaction grants from a policy.
- Linux and Windows desktop bundles are CI-built but remain experimental until real-machine smoke coverage exists. Mobile jobs validate compilation and do not publish store packages.
